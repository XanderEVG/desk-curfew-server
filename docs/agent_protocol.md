# Протокол агента desk-curfew (рабочая памятка)

Живой документ. Сюда записываем все договорённости по протоколу
и семантике команд, чтобы позже собрать из него промт для разработки агента.

## Транспорт

### Агенты → сервер: HTTP

Агенты общаются с сервером **по HTTP**, один эндпоинт:

```
POST /api/agent/hb
Authorization: Bearer <agent_token>
```

Подробный контракт (формат запроса/ответа, авторизация, примеры) —
в [docs/agent_http_protocol.md](agent_http_protocol.md).

- Токен выдаётся в веб-интерфейсе на странице ПК, хранится в `config.ini` агента.
- Интервал heartbeat: ~10 секунд (серверный `heartbeat_interval` = 30, но
  сервер адаптируется по факту — `usage` считается по реальным интервалам).
- Команды от сервера приходят в ответе на hb (массив `commands`).

### MQTT: только для внешних интеграций

MQTT используется **только** для двух вещей:

| Топик | Направление | Назначение |
| --- | --- | --- |
| `server/cmd` | внешнее → сервер | Управление сервером (lock/unlock/add_time) |
| `server/status` | сервер → внешнее | Retained-статус сервера (обновление каждые 60 с) |

Где `{pc}` — имя ПК из БД (`evgeny_pc`, `andrey_pc`).

Агенты **не** используют MQTT. Топики `{pc}/hb`, `{pc}/status`, `{pc}/event`,
`{pc}/cmd` больше не используются.

## Команды сервер → агент (через HTTP, в ответе на hb)

### `{"action": "lock_now", "reason": "...", "info": {...}}`
Немедленно заблокировать рабочий стол. После фактической блокировки
опубликовать `event locked` с reason.

### `{"action": "lock_in", "delay_seconds": N, "reason": "...", "info": {...}}`
Показать предупреждение с обратным отсчётом на N секунд
(`event warning_shown`), по истечении — заблокировать и прислать `event locked`.

### `{"action": "unlock", "reason": "..."}`
Снять блокировку, прислать `event unlocked`.

### `{"action": "add_time", "minutes": N}`
ИНФОРМАЦИОННАЯ команда. Показать уведомление «+N минут»,
при желании обновить индикатор оставшегося времени на экране блокировки.
**Агент НЕ разблокирует сам**: сервер пересчитал бонус и, если нужно,
пришлёт `unlock` отдельной командой.

### Блок `info` (данные для экрана блокировки)

Сервер считает, агент только рисует:

```json
"info": {
  "display_name": "Компьютер Евгения",
  "reason": "daily_limit",
  "reason_ru": "Время за компьютером на сегодня закончилось",
  "locked_at": "2026-10-05T19:42:00+05:00",
  "unlocks_at": "2026-10-06T10:00:00+05:00",
  "next_window": "10:00–20:00"
}
```

- `reason`: `daily_limit` | `schedule` | `manual`.
- `manual`: `next_window` = «до конца дня», `unlocks_at` = конец дня.
- `daily_limit` без расписания: `next_window` = «завтра», `unlocks_at` = null.

## Агент → сервер (через HTTP hb)

### Heartbeat каждые ~10 с

```json
POST /api/agent/hb
Authorization: Bearer <agent_token>

{"locked": false, "lock_reason": null, "idle_seconds": 0, "active_user": "имя", "events": [...]}
```

- **hb шлётся ВСЕГДА** (и в простое) — сервер различает «ребёнок отошёл»
  и «агент умер/ПК выключен».
- `idle_seconds` — секунд с последнего ввода (мышь/клавиатура),
  считать через `GetLastInputInfo` (Win32, без админа).
- `events` — массив событий с момента прошлого hb (подробности —
  в [docs/agent_http_protocol.md](agent_http_protocol.md)).
- Учёт времени на сервере (порог `idle_threshold_seconds`, дефолт 120):
  - `locked=true` → `locked_seconds += interval`;
  - `idle_seconds >= порога` → `idle_seconds += interval` («отошёл», лимит не тратится);
  - иначе → `active_seconds += interval`.
- Сервер выставляет `pc.is_idle` для дашборда (бейдж «отошёл»).
- Если сервер хочет блокировку, а агент шлёт `locked=false` — сервер
  немедленно положит `lock_now` в очередь (заберётся следующим hb,
  троттлинг 120 с). Агенту быть идемпотентным: повторный `lock_now`
  в заблокированном состоянии — no-op + `event locked`.

### `{pc}/status` (retained) — УДАЛЕН
Раньше использовался в MQTT. Теперь статус передаётся через hb.

### `{pc}/event` — УДАЛЕН
Раньше использовался в MQTT. Теперь события передаются в массиве `events`
внутри hb.

## Управление сервером (`server/cmd`)

Внешние приложения управляют сервером, публикуя JSON в `server/cmd`:

```json
{"action": "lock", "pc": "evgeny_pc", "reason": "manual", "delay_seconds": 0}
{"action": "unlock", "pc": "evgeny_pc"}
{"action": "add_time", "pc": "evgeny_pc", "minutes": 30}
```

- `lock` — аналог кнопки «Заблокировать» (reason/delay_seconds опциональны).
- `unlock` — разблокировка.
- `add_time` — бонусное время; НЕ снимает schedule/manual-блокировки.
- Неизвестный ПК или action → warning в лог, действие не выполняется.

## Статус сервера (`server/status`, retained, обновление каждые 60 с)

```json
{
  "online": true,
  "ts": "2026-10-05T12:00:00+00:00",
  "pcs": {
    "evgeny_pc": {
      "display_name": "Компьютер Евгения",
      "is_online": true,
      "is_idle": false,
      "is_locked": false,
      "lock_reason": null,
      "desired_locked": false,
      "desired_lock_reason": null,
      "manual_lock_until": null,
      "last_seen_at": "2026-10-05T11:59:30+00:00",
      "last_active_user": "kid1",
      "active_seconds": 3600,
      "locked_seconds": 0,
      "idle_seconds": 0,
      "bonus_seconds": 1800,
      "limit_seconds": 9000
    }
  }
}
```

## Серверная семантика (учитывать в агенте)

- Оффлайн: нет hb дольше 90 с → сервер помечает ПК оффлайн и не шлёт команды.
- Resend: сервер хочет блокировку, но `event locked` не пришёл за 120 с —
  сервер повторно шлёт `lock_now` (плюс немедленно по heartbeat,
  если последняя команда старше 120 с).
- Перезагрузка ПК: агент стартует → hb/status → сервер сам дошлёт lock.
- Ручная блокировка действует до 00:00 серверной таймзоны (Asia/Yekaterinburg).
- Дневной лимит: `active_seconds >= лимит_дня * 60 + bonus_seconds`.
- `bonus_seconds` (подаренное время) сгорает в 00:00 и НЕ снимает
  блокировки по расписанию и ручные — только по лимиту.
- Лимит может отличаться по дням недели (`day_limits` у ПК).

# Дизайн агента (Windows 10/11, выжимка решений)

## Окружение и запуск

- На детских ПК одна учётка — админская; агент работает **elevated**.
- Elevated-агент: неповышенный Диспетчер задач НЕ может завершить процесс;
  LL-хук видит ввод всех неповышенных программ.
- Автозагрузка: задача Task Scheduler `/sc onlogon /rl HIGHEST`
  (elevated без UAC-промта). Не служба (session 0 не рисует UI),
  не Run-ключ (стартует без повышения).
- Упаковка: PyInstaller onefile + `--uac-admin` (ручной запуск тоже elevated).
- При установке проверять, что UAC включён
  (`HKLM\...\Policies\System\EnableLUA` = 1) — на нём держится защита.

## Конфиг `config.ini` рядом с exe

- `pc_name` — имя ПК из БД;
- креды брокера (те же, что у сервера);
- `pin_hash` — хеш PIN родителя (если пуст — агент просит создать PIN
  при первом запуске);
- `fail_open_hours` — дефолт 12, `0` = выключено.

## Что МОЖЕМ (user-mode + elevation)

- Полноэкранный BSOD без рамки, topmost, поверх таскбара
  (PySide6: `FramelessWindowHint + WindowStaysOnTopHint + showFullScreen`).
- Скрыт из Alt+Tab и таскбара (`WS_EX_TOOLWINDOW`), игнор Alt+F4 / WM_CLOSE.
- Глобальный LL-хук клавиатуры (`WH_KEYBOARD_LL`, ctypes): в блокировке
  глотаем `Win`, `Alt+Tab`, `Win+D`, `Ctrl+Esc`, `Alt+F4`.
- Тосты поверх всех окон без кражи фокуса (`WS_EX_NOACTIVATE`).

## Что НЕ МОЖЕМ (принято; роадмап ужесточения)

- Перехватить Ctrl+Alt+Del; запретить повысить Диспетчер задач через UAC-промт
  (ребёнок-админ может кликнуть «Да»).
- `BlockInput()` не используем сознательно: убил бы секретную комбинацию.
- Позже, если дети разберутся: watchdog-пара, службы, политики против
  Диспетчера задач.

## Аварийный доступ

- Комбинация **Ctrl+Alt+Shift+F12** (работает в любом состоянии, ловится
  LL-хуком даже в блокировке) → topmost PIN-пад.
- Верный PIN → меню: «Разблокировать» / «Закрыть агент» / «Отмена».
- Неверный PIN → тихо закрыться + `event pin_attempt`.
- **Fail-open**: нет связи с брокером `fail_open_hours` подряд и агент
  заблокирован → разблокировка + `event fail_open`.

## Экран блокировки (BSOD-стиль)

- Шрифты системные: Segoe UI Light («:(», заголовки), Segoe UI (текст),
  Consolas (стоп-код и техстроки).
- Контент рисуется из `info`: «:(», `reason_ru`, `display_name`,
  текущие время/дата/день недели, «Разблокировка: …» (`unlocks_at`,
  `next_window`), «Использовано сегодня», стоп-код
  `CURFEW_DAILY_LIMIT` / `CURFEW_SCHEDULE` / `CURFEW_MANUAL`,
  «Если это кажется ошибкой — попроси родителей добавить времени 🙂».

## Тосты агента

- `lock_in`: «⏰ Через N минут компьютер заблокируется — сохрани прогресс».
- `add_time`: «+N минут».
- `unlock`: «Разблокировано».

## Стек

PySide6 (UI) + paho-mqtt (отдельный поток, мост в Qt через сигналы/очередь).
